# G3 integrated copy-back evaluation

Decision: **defer M5 retained-frame implementation**. G3 evaluation is complete;
M5 is not implemented. The optional copy-back path demonstrates lower CPU use
on this host, but a retained-frame path has not demonstrated a further net
benefit. Current-path qualification subsequently concluded with the user-approved
optional endurance exception; see [candidate acceptance](CANDIDATE.md). No
retained-frame benefit was demonstrated by that qualification. Software remains the default.

## Measured evidence

The [full comparison](../../results/m4/integrated-2026-09-07T19-30-43.280Z/result.json),
[raw samples](../../results/m4/integrated-2026-09-07T19-30-43.280Z/raw.jsonl), and
[verified assessment](../../results/m4/integrated-2026-09-07T19-30-43.280Z/result.assessment.json)
follow the [predeclared protocol](../M4-MEASUREMENT-PROTOCOL.md). All six fresh-browser
samples passed. All 264 recorded foreground checks matched, each teardown left
zero workers, process membership remained stable during measurement, and
runtime/protocol hashes were unchanged. Raw records match the saved sample arrays.

Host: Apple M1, 8 GiB RAM, Darwin 25.5.0, Chrome 152.0.7977.76. Each browser
warmed playback for 30 seconds before a nominal 60-second measurement; sampled
CPU intervals were 59.97–61.14 seconds. The identical front-index 1080p30 H.264/AAC
fixture played at 1920×1080 through 10 Mbps / 80 ms loopback shaping. Browser
startup and origin identity-cache initialization were outside measured intervals.

Median paired CPU reduction is **20.12%**. Sample median process-family RSS
ranged from 1165–1407 MiB for software and 1145–1444 MiB for optional decoding;
this does not establish a consistent memory benefit or long-run stability.

## Decision and limits

The current path sustains delivery and saves CPU in all three pairs. The measured
2.23–2.61 ms per copied frame is asynchronous `copyTo` wall time, not CPU usage.
It excludes allocation, staging into Wasm, native planar conversion and unknown
browser/driver traffic. It cannot quantify the savings of removing copy-back.
No retained-frame path, energy metric or hardware-acceleration benefit was measured.

A retained-frame path would add image/filter/renderer ownership, explicit
downloads for CPU filters, separate ASS composition and bounded lifetime handling.
Those costs are not justified by a measured retained-frame benefit yet. Defer M5
and preserve the working copy-back architecture. Reopen G3 when current-path G1
passes and a concrete workload or measured bottleneck motivates a bounded
prototype that preserves filters, subtitles, fallback and frame ownership.

This short comparison does not replace independent hour-long sync/memory
qualification. Software subsequently passed full G1 requalification; the user accepted the
optional 57:38 run with an explicit exception. The original optional strict
gate result remains failed. M3's historical investment-gate failure is unchanged; the integrated
protocol did not declare a new numerical investment threshold. Earlier failed
G3 attempts remain recorded in [M4 validation](M4.md). No Docker was used.
