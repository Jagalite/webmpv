# M0 acceptance record

Status: **complete**, accepted 2026-09-06 at 21:17 UTC. Nine browser acceptance
checks and four AudioWorklet tests pass against the final container build.

## Scope

This milestone implements the architecture's original build and local software
playback. The frozen profile is [M0-PROFILE.md](../M0-PROFILE.md). It qualifies the
checked-in 12-second 640x360 H.264 B-frame/AAC stereo/ASS fixture on this Apple M1
Mac with Google Chrome. It is not G1 standalone-player qualification.

mpv owns playback, decoding coordination, seeking and synchronization. Upstream
FFmpeg performs software audio/video decode; libass composes ASS through the
public libmpv software render API. Canvas 2D presents the CPU frame. The original
browser AO feeds bounded stereo Float32 PCM to an AudioWorklet connected to the
audio destination. No VideoDecoder, AudioDecoder, VideoFrame, MSE or native media
playback path is used by the engine.

## Browser acceptance

The test removes browser decoder globals and forbids HTMLMediaElement.play().
The same test runs against the packaged Wasm/JavaScript files served locally with
COOP/COEP. It checks:

- Native initialization and actual H.264/AAC decoder/track events.
- Changing visible canvas frames and nonzero PCM from the connected audio graph.
- Pause stability, exact local seeking and visible styled ASS. Hiding subtitles
  changes pixels in the subtitle region; restoring them restores the image hash.
- Resizing, volume commands, resume, end-of-file and reopening in the same instance.
- Graceful native destruction, closed AudioContext and rejected subsequent use.
- Ten additional create/open/play/destroy cycles with no retained dedicated
  workers, plus invalid input and destruction during initialization.

Four independent AudioWorklet tests cover variable render quantum sizes, ring
wrap, underrun clock behavior, pause/reset stale-data suppression and closure.
The analyser establishes actual browser audio graph output; no physical speaker
measurement or independent A/V synchronization measurement is claimed.

## Build acceptance

Canonical build: ARM64 Linux container, pinned Ubuntu base, stock Emscripten
4.0.14, verified SDK and Node archive hashes, fixed Python build tools and a lock
for every installed Debian package. Each application build starts in empty
`/work`, with verified source archives and no prebuilt application objects or
engine files copied in. The two builds use independent writable container
filesystems. Their final artifact hashes are compared separately.

The initial x86 container attempt was replaced with native ARM64 compilation
because emulation on the M0 Mac was slow. The codec, browser, fixture, playback
and resource profile was not changed. The final acceptance uses the native
container artifacts.

See [PATCHES.md](../PATCHES.md), [PROVENANCE.md](../PROVENANCE.md), source/toolchain
locks, copied upstream notices, `results/m0-baseline/build-manifest.json` and the dependency
inventory `results/m0-baseline/sbom.cdx.json` for inputs and flags.

## Deliberate M0 boundary

Local files are copied into stock in-memory WasmFS and limited to 32 MiB. Remote
range I/O, bounded remote streaming and cancellation belong to M1. Long-run
memory and A/V sync, broad subtitle fidelity, 1080p performance, larger track and
codec corpora, network faults and cross-browser/device coverage remain M2/G1.
No later browser decoder integration is authorized or implemented by M0.
