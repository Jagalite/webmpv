# M1 acceptance record

Status: **complete**. The software player streams indexed MP4/MKV through the
browser range broker and public mpv stream callbacks. The supplied 1.63 GB MKV
starts audio/video without materializing the whole file, renders its embedded
ASS, seeks to 1440 seconds, and recovers from a stalled actual demux read by
presenting the replacement 60-second target.

The reference device and frozen budgets are in
[M1-M2-PROFILE.md](../M1-M2-PROFILE.md). [Browser evidence](../../results/m1/browser.json)
records the browser, exact Wasm hash, timings, actual PCM consumption, presented
positions, transport aborts and native interruption counters. At a paused
6-second position in the user's file, hiding ASS changes visible pixels and
restoring it reproduces the original image. Private source media and screenshots
remain outside the release.

One independent I/O worker owns Fetch, authorization and the bounded LRU. A
256 KiB mailbox connects it to synchronous native reads. Offsets remain 64-bit;
the reader tests include positions above 4 GiB. Strong representation checks,
bounded retry/backoff, truncation resumption and terminal cancellation prevent
accidental full-file downloads and false EOF. Seek interruption is separate
from terminal close; ticketed mailbox state prevents stale read publication.

mpv still owns demuxing, FFmpeg software decoding, seeking, synchronization,
track selection and libass composition. The original AO reports consumed PCM
and browser output latency to mpv. The browser host suppresses obsolete canvas
and PCM presentation across seeks. No browser decoder or native media fallback
is used.

The TypeScript API includes remote/local open, play/pause, seek, track selection,
subtitle visibility, volume, rate, resize, diagnostics and asynchronous destroy.
Late authorization renewals use unique IDs so a failed source cannot satisfy
the replacement source's pending request. See the
[integration guide](../INTEGRATION.md) and small `web/example.html` host.

The engine's two independent clean builds are compared in
[reproducibility.json](../../results/m2/reproducibility.json). Browser sidecars are
assembled independently from the native compilation and compared in
[bindings-reproducibility.json](../../results/m2/bindings-reproducibility.json).
The latter includes the final authorization-ID correction. Native build
manifests retain their original browser snapshot; release/runtime manifests
identify the final sidecars. M2 adds sustained qualification and its release
acceptance record; M1 completion alone does not pass G1.
