## Results

CPU percentages are relative to one core and include the benchmark Chrome
process family, including GPU-process CPU time. They are not GPU utilization or
energy measurements. Reductions are computed per paired repetition; the median
of those reductions is not the ratio of the median CPU values.

| Path | CPU per repetition | Median CPU | Pixel equivalence | Timed delivery |
|---|---|---|---|---|
| FFmpeg/Wasm software | 49.96%, 45.57%, 40.70% | 45.57% | Reference | All PTS exact; no frame >33.334 ms late |
| WebCodecs copy-back | 35.05%, 27.24%, 26.01% | 27.24% | All four sampled RGB grids byte-identical | All PTS exact; no frame >33.334 ms late |
| Retained VideoFrame | 15.46%, 11.69%, 9.63% | 11.69% | **Fails:** p99 difference 23–25, limit 16 | All PTS exact; no frame >33.334 ms late |

Copy-back CPU reductions were **29.83%, 40.21%, 36.11%**: median **36.11%**,
with every pair above 20%. Thus the CPU-benefit test passes. Retained timing is
diagnostic only; it cannot support an equivalent-output performance claim.
The differing retained output is not proof of worse perceptual quality; it
fails the specific numerical equivalence criterion declared for this experiment.

Wasm heaps stayed at 128 MiB. Outstanding packet/frame peaks were four for
software and eight for browser paths. Maximum Canvas-submission lateness was
14.50 ms, 7.85 ms and 21.61 ms respectively. No uncaught page or decoder error
occurred; swscale's unaccelerated-conversion warning is retained as diagnostic
stderr. Visibility remained `visible` throughout.

**Memory gate failure:** the first software repetition grew **73.64 MiB** in
process-family median RSS, above the 64 MiB limit. The remaining software
repetitions declined by 4.16 and 243.53 MiB. Copy-back growth was -199.64, +4.09
and -9.05 MiB. These observations do not establish a leak; process caches,
allocation and preceding runs can affect RSS. They also do not justify dropping
the failed first repetition. The overall copy-back candidate assessment is false
because its software comparison did not pass every correctness/resource gate.

The standalone reset/preroll probe reached exactly 17.5 seconds in 269.41 ms
(software), 87.81 ms (copy-back) and 92.77 ms (retained). These are single decoder
probes, not full-player seek guarantees. Timed first-presentation/reset costs
were 20.41–62.48 ms, 8.03–37.90 ms and 3.38–26.31 ms respectively; module loading
and corpus fetch/transfer are recorded separately.

Mean stage times per frame: software conversion plus Wasm-to-ImageData copy
3.19 ms; copy-back browser readback 4.12 ms, upload 0.17 ms, planar normalization
plus conversion/copy 3.47 ms. These are elapsed stage times, including asynchronous
waiting where applicable, and must not be summed as process CPU time.

## Setup corrections retained

The first smoke failed because Chrome produced NV12 rather than I420. The
second accepted NV12 but failed pixel comparison. Normalizing NV12 to planar
I420 inside Wasm made the copy-back sampled output exactly match software; its
cost remains included. The third smoke verified that correction and retained
presentation's continuing pixel mismatch. All smoke directories remain under
`results/m3`; none qualifies as performance evidence. No threshold was relaxed.

Before the paced run, the contract recorded that retained measurements would
remain diagnostic while copy-back was independently assessed against software.
Both CPU-backed paths reuse ImageData as the production worker does. No changes
were made to measured source/runtime files during the timed run.

## Limits and next work

This is a video-only matched packet/decoder/output experiment using a synthetic
1080p30 H.264 fixture. It is not the accepted mpv player. It excludes audio, ASS,
networking, mpv scheduling, fallback, power and long-duration thermal behavior.
Browser-decoder hardware selection remains unknown. Three paired repetitions
provide an observed range, not statistical confidence across devices or media.
CPU costs fell over successive repetitions in every path; warming/caching or
other time-dependent effects remain a source of uncertainty.

Packet-message costs cover transfer of the preloaded corpus and progress
messages. A future per-packet mpv pthread/browser bridge is **not measured**.
The software path has a peak of four outstanding packets and browser paths
eight, reflecting synchronous versus asynchronous decoder execution. These
harness differences must not be presented as an integrated mpv speedup.
Canvas submission and document visibility are measured; physical display timing,
OS-level foreground occupancy and energy are not independently established.

The next bounded experiment should predeclare a consistent warm-up and process
isolation policy, repeat the unchanged resource/benefit gates, and measure the
intended packet bridge's overhead. Investigate the retained color/chroma output
separately if that path is pursued. Do not begin M4 on these results alone.
The [integration review](../M3-INTEGRATION-REVIEW.md) estimates a narrow M4 effort
at 3–6 engineer-weeks with uncertain recovery/rebase cost; a named owner and
accepted budget are still required at G2.

Validation of the delivered experiment: native Wasm link, TypeScript build,
14 existing range/audio tests, seven assessment rejection/acceptance tests,
full browser run, independent evidence assessment, final screenshot inspection
and input-hash verification. The browser qualification command intentionally
returns nonzero for the failed resource gate. M2 runtime tests and the M2 hour
were not rerun because production runtime files did not change.
