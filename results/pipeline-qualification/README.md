## Evidence boundaries

Functional and browser-clock timing tests below are headless, sequential and separate from foreground CPU tests. Tested versions: Chrome 152.0.7977.83, Firefox 146.0.1, Playwright WebKit 26.0 on the local Apple M1 macOS host. This is not Safari-release, Windows, mobile, HDR, PiP, remote playback or physical speaker/display certification.

The [12:28 suite](suite-2026-09-09T12-28-49.050Z/result.json) passes remux, faults, packet and A/V checks but **fails** two Chrome Software seek cases. It is retained with its input archive. The [12:43 corrected-IO suite](suite-2026-09-09T12-43-48.204Z/result.json) reruns every affected Software driver across the three browsers and adds a deterministic IO regression plus 60 actual-rendered-frame seek checks. Its input archive pins the corrected sources and binaries. Unchanged remux results are not relabeled as a new combined run.

All these functional cases terminate their workers. Long-file remote and local tests do not materialize complete output. Some small sources **are fully consumed**: the approximately 46 KB trimmed sync file, the six-second TS, the 4.7 MB long-GOP MP4 across its seeks, and the roughly 5.1 MB long-GOP TS scanned for random access (8.1 MB fetched before the first playable fragment includes repeated reads). Bounded memory does not mean every source is only partially read, and scan/read totals can include repeat fetches. The historical `fullyConsumed` field is only a fetched-bytes heuristic; actual complete requested coverage is checked from the origin Range unions, not inferred from that field. Demux reaching EOF and reading the whole source are distinct.

The Chrome matrix has the following per-case observations; these are startup/seek timings from correctness tests, not CPU performance estimates:

| Source | First playable fragment | Source bytes before it | Seek recovery samples |
|---|---:|---:|---|
| Indexed movie MKV | 192 ms | 1,838,146 | 130 / 216 / 299 / 94 ms |
| Tail-indexed movie MP4 | 134 ms | 1,662,073 | 324 / 258 ms |
| MP4 with 20-second GOP | 386 ms | 2,949,120 | 190 / 63 / 200 ms |
| Six-second TS | 93 ms | 778,320 | 72 / 64 ms |
| TS with 20-second GOP | 487 ms | 8,114,320 | 569 / 84 / 281 ms |
| Trimmed MP4/preroll | 110 ms | 46,163 | 65 / 56 / 57 ms |

MSE queue depth peaks at one. These cases show approximately 6–10.5 seconds buffered for ordinary GOPs and 24.5 seconds with a 20-second GOP. The complete fragment-size sequence and compressed byte ledger are in each snapshot. The paused-backpressure test holds both source bytes (1,245,184) and generated bytes (565,536) unchanged over its three-second observation.

Bounds are explicit: 2 MiB Range cache, 256 KiB mailbox, 64 KiB source blocks, 1 MiB probe, 4 MiB demux index budget, 2 MiB/256-packet timestamp prefetch, 8 MiB output batch, one MSE batch credit and 12 MiB compressed buffer ledger plus one batch overshoot. Retain the current GOP plus three seconds behind, target five seconds ahead, and evict at safe random-access points. The source-seek scan has packet/byte/backoff limits and can reject inputs beyond them. Browser-owned decoded buffers are not measured by that ledger.

Cancellation records exact pending fragment bytes and a conservative retained-compressed byte upper bound. A terminated producer can have up to one 8 MiB batch in flight; its unobserved partial output is not reported as zero waste. Source retries rebuild only bounded work; identity changes fail explicitly before concatenating content from different objects.

Packet validation matches duplicate packet hashes against their nearest unused timestamp candidate. MP4 timestamps are exact in the sampled capture; MKV known DTS differs by at most 1 ms due to its timebase; the canonical TS comparison has about 0.345 ms rounding. Missing source DTS is reported as unknown, not scored as exact. TS AAC packet comparison uses host FFmpeg stream-copy canonicalization solely as a test reference, not a serving/transcoding requirement.

The flash/beep test maps AudioWorklet onset through `getOutputTimestamp()` against white-frame `requestVideoFrameCallback()` display estimates. In this run sync-source audio follows video by about 12 ms Native / 23 ms remux; MKV about 20 ms; trimmed MP4 about 41 ms for both. The deliberate 250 ms offset measures 271 ms Native / 266 ms remux. These are scheduling estimates with browser-clock uncertainty, not acoustic measurements or a general A/V bound. Initial AudioContext clock mapping is excluded from steady onset matching. These flash/beep trials restart at source time zero; distant-seek tests validate coded timestamps and presentation recovery, not independent physical A/V output after every seek.

## Software rendering correctness

[Chrome's 11 cases](yuv-chrome-2026-09-09T12-45-06.546Z/result.json) include analytic SDR color patches, 10-bit and YUV444 RGB fallback, GPU rotation, CPU filters and animated ASS lifecycle. Four BT.601/709 full/limited patch sets have maximum center-pixel error **0/255** against their analytic expectation. This does not establish exact swscale chroma reconstruction at edges or end-to-end display-profile/transfer-function accuracy.

[Firefox](yuv-firefox-2026-09-09T12-45-56.116Z/result.json) and [WebKit](yuv-webkit-2026-09-09T12-46-35.470Z/result.json) pass their four-case subsets, including the explicit rotated-fallback rejection.

Animated ASS checks seek into existing cues, seek backwards, toggle tracks, resize, transition RGB/YUV output, restore WebGL while playing and paused, and compare paused redraw PNGs. Embedded font/animated cue fixtures reuse the maintained libass extraction. Context resources return to zero live textures on normal destruction; worker count returns to zero. One rotated high-depth fallback case passes by explicit rejection, not rendered support.

The [deterministic IO test](io-epoch-2026-09-09T12-43-50.510Z/result.json) makes the original worker fail the current read after a late old-epoch message; the isolated worker completes the exact bytes with no abort. The [60-seek stress test](seek-stress-2026-09-09T12-43-55.085Z/result.json) confirms actual rendered PTS within 150 ms of every target, with delayed source responses. Twenty seeks each: YUV median 359 ms / max 935 ms; hflip+brightness median 436 ms / max 941 ms; YUV444 RGB fallback median 1,106 ms / max 3,511 ms. These sequential headless samples are not a population latency guarantee.

At 1080p, ordinary GPU video output explicitly copies and uploads 3,110,400 YUV bytes per frame through three textures. RGB fallback uses 8,294,400 bytes and one upload. ASS uploads vary with the changed rectangle. No WebCodecs is needed. The old CPU RGB allocation still exists, so there is no established memory-saving claim. Browser/driver internal copies are opaque.

## Failures retained and corrected

Earlier timestamp/configuration, context-loss and seek failures remain in timestamped directories. In particular: decoderless AAC metadata discovery; MKV source-origin drift; negative-preroll MSE clipping; timestamp TS seek skipping the first IDR; stale GL resource deletion after context restoration; throwing through mpv's locked renderer; and late epoch cancellation of a new read were corrected in the isolated versions. The rotated RGB fallback assertion became a reasoned explicit rejection.

An earlier analytic color fixture accidentally converted pixels while setting metadata; `-v2` fixtures use metadata-only `setparams`. Earlier duplicate AAC payload hash matching chose the wrong equal-payload packet; the current packet test consumes nearest unused candidates. Neither earlier failed result is silently replaced. [WebKit cadence evidence](webkit-cadence-2026-09-09T12-25-11.132Z/result.json) shows why raw total-frame counters were unsuitable for its functional cadence gate; actual presented callbacks are approximately 30 fps for both Native and remux.

Native ASS/audio adaptation, generated-track presentation and new Hybrid effects were not added as extra major experiments. The previous source-backed investigation remains their evidence boundary. Promotion requires the routing/UI/unsupported-format contracts listed in the findings; a green narrow test suite does not imply broad media support.

## Matched visible performance

Each row below is its own sequential ABBA comparison with two fresh Chrome processes per arm, AC power, Apple M1/8 GiB, a 960×540 visible surface backed by 1920×1080 playback, matching audio/subtitle/filter selections, and verified foreground state. No build or other qualification browser ran alongside these measurements. CPU is summed CDP browser-process CPU-time delta, 100% = one core. It excludes WindowServer, external VideoToolbox services and the Node HTTP origin. Summed process RSS can double-count shared pages. First-frame time means the harness's first observed frame counter, not physical display onset.

| Separate run | Baseline CPU mean (range) | Candidate CPU mean (range) | Playback gate |
|---|---:|---:|---|
| [Movie Software → YUV](visible-2026-09-09T12-47-17.248Z/result.json), 10 s warmup + 30 s at source 236.9 | 62.54% (47.06–78.02) | 41.27% (36.04–46.50) | Four trials pass |
| [Animated ASS Software → YUV](visible-2026-09-09T12-50-37.983Z/result.json), 1 s warmup + 7 s at source 2 | 55.63% (53.96–57.30) | 51.20% (50.84–51.56) | Four trials pass |
| [Movie Native direct → remux](visible-2026-09-09T12-52-01.427Z/result.json), 10 s warmup + 30 s at source 236.9 | 15.51% (13.87–17.15) | 17.70% (15.33–20.06) | Four trials pass |

The descriptive within-run CPU reductions are 34.0% for YUV movie and 8.0% for YUV ASS; remux costs 14.1% more than Native direct in its comparison. **The movie variability is large, samples are small, and these are not stable production effect estimates.** Do not combine them with the older investigation or decoder-stage measurements. The comparison also includes the isolated IO correctness fix in the YUV arm, rather than pretending it is a pure renderer-only ablation.

All twelve trials have zero exposed drop-counter increments, no process churn and zero surviving workers. Software/YUV have zero measured audio underruns. Their maximum observed mpv A/V discrepancy is 16 ms in the movie run and about 11 ms in the ASS run. Native/MSE do not expose equivalent audio-underrun or internal decoder-drop separation counters; those fields remain unavailable, not zero. The browser-clock A/V test above supplies separate Native/remux evidence. A dedicated scheduling-lateness histogram and physical first-audio startup are not instrumented; render/pump timings and audio diagnostics are retained as their actual fields without relabeling them.

Movie first-frame observations range 792–1,810 ms Software and 678–2,902 ms YUV; animated ASS 747–1,194 ms Software and 757–1,012 ms YUV. Native direct is 220–342 ms and remux 254–338 ms in its paired run. Cache/initialization variance and the observation method preclude a startup-speedup claim. Each result retains the original per-trial startup state, CPU/RSS samples, foreground checks, audio diagnostics and cleanup.

In the paired remux run, first playable fragments take 188 / 73 ms after 1,572,864 / 1,507,328 source bytes. Each trial generates 16,669,116 bytes over its startup/warmup/measurement lifecycle; observed output batches range 34,250–754,716 bytes. Peak compressed ledger is 6,146,762 bytes, buffered duration 16.43 s, MSE queue depth one, source cache 2 MiB and Wasm heap 64 MiB. Source fetch is 17.63 / 17.37 MB of the 248.81 MB movie; complete-source processing did not occur.

Each seven-second measured YUV ASS interval submits 208 frames, 624 video plane uploads and 646,963,200 copied/uploaded video bytes. It performs 32 subtitle rectangle uploads totaling 145,667,200 bytes. This is still substantial subtitle upload work; “dirty rectangle” does not mean negligible cost. Steady video readback counters are zero at the application boundary, which is not a zero-copy claim.

## Final lifecycle and startup checks

The final [guard/startup suite](suite-2026-09-09T13-07-10.382Z/result.json) archives the final inputs and passes. [Three-browser lifecycle injection](remux-lifecycle-2026-09-09T13-07-12.557Z/result.json) dispatches an error from a superseded SourceBuffer after a real seek: it must not stop the current generation. A current-buffer error must stop production, explicit reopen must recover, and seeking a destroyed player must reject without spawning workers. The final changes add the generation guard, clear stale append receipts and reject restart after destruction. The visible measurements precede these guard-only changes; their normal playback logic is unchanged. They are not silently relabeled as post-guard measurements.

[Eight startup observations](audio-startup-2026-09-09T13-07-24.199Z/result.json) use the same short AVC/AAC sync fixture, a preloaded AudioWorklet probe, and fresh headless Chrome processes. First non-silent decoded-audio callbacks arrive after 79–138 ms Native, 122–129 ms remux, 209–451 ms Software RGB and 191–221 ms YUV. This records callback receipt, including message scheduling; it is not physical first sound. Native/remux audio is routed through Web Audio for instrumentation. These startup observations are separate from the visible performance runs and do not establish a startup speedup.
